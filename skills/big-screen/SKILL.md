# big-screen — B 端数字大屏设计 / 评审 skill

## 核心原则

> **大屏不是"普通界面放大版",而是销售场景里给客户决策者看的"价值表达物"。**
> 第一受众是客户的决策层(老板/高层),不是日常使用者。所有取舍(放什么、突出什么、用什么色)都要按决策者本位来。

方法论来源:汤圆《B 端体验设计入门课》第 04/05/06/07/11/17 讲。

## 何时使用

**用 design 模式**:
- 新项目要做大屏,从 0 到 1 出方案
- 已有大屏被客户领导吐槽,要重做

**用 review 模式**:
- 设计稿已经有了,做交付前体检
- 准备给客户演示前,做最后一轮风险排查

**不要用本 skill**:
- 普通后台/中台的常规界面设计 → 那是 B 端常规体验设计,不是大屏场景
- 给一线运营 7×24 小时挂着用的指挥屏 → 决策者本位不适用,要切换成执行层本位

## 模式判断

```
用户输入
  ├─ 含 "审"/"评审"/"体检"/"review"/"检查" → review 模式
  ├─ 含 "设计"/"方案"/"做一个"/"design"/"新做" → design 模式
  └─ 不明 → 询问:"你是要(A)从 0 出方案,还是(B)体检已有设计稿?"
```

## 入参收集(两个模式都要)

如果用户没说,**一次性**列出下面的清单让用户补充,不要逐项追问:

| 项 | 说明 | 必填 |
|---|---|---|
| 行业 | 餐饮监管 / 医疗 / 制造 / 政务 / 能源 / 物流 / 金融 / 互联网 / ... | ✅ |
| 客户类型 | ToG / 央国企 / 大型民企 / 中小企业 / 互联网公司 | ✅ |
| 业务目标 | 这套大屏要呈现什么业务?核心数据卖点是什么? | ✅ |
| 第一受众 | 决策者 / 管理层 / 执行层(默认决策者) | ✅ |
| 目标硬件 | 屏比例和分辨率(19:6 / 4:3 / 21:9 / 32:9 / LED 拼接墙 / 未定) | 推荐 |
| 客户触达度 | 能直接访谈 / 只能通过销售转述 / 完全无法接触 | 推荐 |
| 团队 3D 能力 | 无 / 会 C4D 类 / 会 Unity | 可选 |
| 客户审美锚 | 客户参观过/称赞过的样板项目、客户公司装修风格图 | 可选 |

# 模式 A:design(从 0 出方案)

按下面 6 步顺序执行,**不要跳步**——大屏翻车 90% 是因为跳过 Step 1-3 直接做视觉。

## Step 1:业务理解(产业链 + 时间链)

**产出**:5 行内的"业务理解小卡片"

- **产业链定位**:上游/中游/下游分别是谁?产品在哪一环?**对下游的不可替代价值**是什么?(这就是客户最关心的卖点)
- **时间链分析**:行业经历过 [手工 → 电子化 → 数字化 → 智能化] 哪几个阶段?**贯穿所有阶段不变的需求**是什么?(这是真正要在大屏上突出的)
- **量化锚点**:至少找 1 个能算出业务价值的数字(原本人力成本 X 元、检查次数 Y 万次、错误率 Z%),用于后续大屏作为"价值数字"展示。

> 例(明厨亮灶):上游是硬件/算法供应商,中游是监管平台,下游是餐饮门店。不变的需求是「监管的人效、实时性、准确度」。量化锚点:原本检查人力成本 ≈ 45 亿/年。

## Step 2:信息收集与筛选 → 信息优先级表

**收集来源**(按优先级):
1. **5–10 年的行业报告 / 政府白皮书 / 头部企业年报** — 看每年都摆在最前面的数据
2. **客户对应部门的 KPI** — 决策者最关心的指标
3. **同类产品官网的功能宣传** — 反复出现的就是行业共识

**优先级分级规则**:

| 等级 | 判定标准 |
|---|---|
| **P0** | 报告里反复出现 + 摆在最前面 + 对应核心 KPI(如 GDP / 违规检出数 / 服务人次) |
| **P1** | 报告里高频出现 OR 对应一线 KPI |
| **P2** | 仅特定客户提到 / 锦上添花的补充信息 |

**产出**:信息优先级表

| 数据项 | 优先级 | 来源依据 | 对应受众 | 备注 |
|---|---|---|---|---|
| ... | P0/P1/P2 | 行业报告 X / KPI Y | 决策/管理/执行 | ... |

> ⚠️ 没有这张表就跳到布局,后面适配一定会砍错数据。

## Step 3:受众与场景研究(决策链 + 观察法)

### 3.1 利益相关者画布

按决策链分三层(默认大屏 = 决策者本位):

| 层 | 关心什么 | 在大屏上呈现 |
|---|---|---|
| **决策层** | 经营结果、价值数据、对外形象 | 整体营收/效益数据、对比指标、品牌感视觉 |
| **管理层** | 部门 KPI、权限、风险预警 | 部门维度统计、异常告警、权限可视 |
| **执行层** | 操作效率、流程顺畅 | (大屏一般不服务此层,除非是指挥中心场景) |

### 3.2 观察法(无法接触客户时必用)

人是环境的产物。无法访谈客户时,反推他们的偏好——分析 3 件事:

1. **客户最高频使用的产品** → 影响他对界面的下意识习惯
2. **客户最典型的工作场景照片** → 看 摆放规整度 / 字号 / 信息密度 / 色调
3. **客户见过最"高级"的同类产品是什么样** → 这就是他心里"高级感"的锚

### 3.3 认知映射

把观察到的偏好直接翻译成设计选择:

| 观察到 | 映射到设计 |
|---|---|
| 桌面物品全部对齐、横幅大字、规整 | 大屏要规整对齐到栅格,字大,信息清晰 |
| 工作环境冷色调多(南方/沿海) | 主色用蓝色系 |
| 工作环境暖色调多(北方政府) | 主色用红色系 |
| 客户称赞过 Windows 7 桌面 | 蓝色玻璃质感、半透明、轻发光 |
| 客户公司装修=智慧工厂(白+品牌色+玻璃) | 大屏走白底+品牌色+玻璃质感+发光 |
| 互联网客户工位个性化 | 预判会提"自定义布局"需求,提前设计 |

**产出**:决策者审美锚定描述(3-5 行,用类比说清楚)
> 例:客户是地市级食药监,最高级的参考是省级指挥中心大屏(深蓝+大字+柱状统计)。所以本项目走 深蓝底 + 浅蓝数据 + 大字号 + 规整栅格,**禁止**黑+黄(撞火灾)。

## Step 4:布局与多分辨率适配

**核心规则**:
- **以 19:6 为基准**(文中经验值,实际项目以客户硬件为准)
- 向下兼容 4:3,向上兼容 21:9
- **中间放 P0(任何分辨率都不能砍)**
- **两侧放 P1/P2**(窄屏隐藏次要侧,宽屏增加补充数据)
- **设计时就固定一边作为"次要侧"**,窄屏统一砍这一侧

**产出**:三档 ASCII 草图

```
[21:9 宽屏 — 两侧加 P2 补充]
+----+----------+--------------------+----------+----+
| P2 |    P1    |        P0          |    P1    | P2 |
+----+----------+--------------------+----------+----+

[19:6 基准]
+----------+--------------------+----------+
|    P1    |        P0          |    P1    |
+----------+--------------------+----------+

[4:3 窄屏 — 砍掉次要侧 P1]
+----------+--------------------+
|    P0    |     次要 P1        |
+----------+--------------------+
```

> ⚠️ **常见翻车**:适配时随便砍,把 P0 数据砍了 → 决策者价值感大幅削弱。

## Step 5:视觉方案 + 行业禁忌检查

### 5.1 视觉风格选择

基于 Step 3 的认知映射,先定:**底色 / 主色 / 质感 / 光效 / 字号档**。

### 5.2 行业基调与禁忌速查表

(经验值,**必须用 Step 3 的实际观察校准**,不能直接照搬)

| 行业 | 推荐基调 | 高级感元素 | ❌ 禁忌色彩 / 元素 | 禁忌原因 |
|---|---|---|---|---|
| 制造业 / 工业 | 白底 + 品牌色 | 玻璃质感、发光、机械结构线 | — | — |
| 政务 / 国企 | 蓝/红 + 大字规整 | 严肃对齐、栅格、清晰 | 花哨/卡通配色、自定义布局 | 严肃场景不容犯错 |
| 餐饮卫生监管 | 蓝/绿 + 浅底 | 摄像头识别图标、统计图 | **黑底 + 黄字** | 客户长期看火灾标志,潜意识联想 |
| 医疗 | 浅蓝/浅绿 + 白底 | 数据可视化、清爽分区 | 大面积红色 | 联想到血液 |
| 电力 / 能源 | 深蓝 + 品牌色 | 电网线条、流光 | 高亮黄黑斜条 | 高压警戒标志 |
| 物流 / 运输 | 蓝/橙 + 地图底 | 路径动画、轨迹 | 红白闪烁 | 急救/事故联想 |
| 金融 / 银行 | 深蓝/金 + 深色 | 精致图表、高品质字体 | 大面积纯黑 | 暗合"亏损/丧" |
| 互联网 | 深色酷炫 / 浅色简洁 | 渐变、3D、个性化 | 政务范的严肃栅格 | 不符合调性 |

### 5.3 视觉自查清单

- [ ] 主配色和客户行业的高危标志色撞了吗?(对照上表)
- [ ] 决策者所在地区是南方(冷色)还是北方(暖色)?
- [ ] 视觉元素(玻璃/发光/3D)和客户认知中的"高级"匹配吗?
- [ ] 字号在最远观看距离下能否一眼读到?(政务/制造场景尤其严苛)

## Step 6:实现路径推荐

按团队 3D 能力分档:

| 团队能力 | 推荐路径 | 工具 / 平台 |
|---|---|---|
| 无 3D 经验 | Web SaaS 模板,挑模板改 | 阿里 ThingJS / DataV / 网易数可视 |
| 会 C4D 类 | 静帧/视频 + SVG 路径联动数据 | Win:C4D + Octane Render;Mac:C4D + Arnold 或 Blender |
| 进阶 | Unity + Shader(Shader 找研发合作,设计师别独自啃) | Unity + Unity Hub 素材库 |

## 最终产出

把 Step 1–6 的产出合成一份 Markdown 文档,默认保存到:
`docs/big-screen-design/<项目名>-spec.md`

文档结构:
1. 业务理解小卡片
2. 信息优先级表
3. 决策者审美锚定描述
4. 三档 ASCII 布局草图
5. 视觉方案(底色/主色/质感/光效/字号档) + 禁忌自查
6. 实现路径建议
7. 风险点 / 待和客户/销售确认的事项

# 模式 B:review(体检审查)

## 入参

- 设计稿截图 / 描述 / 现有方案文档路径
- 项目背景(沿用 design 模式入参表)
- 评审深度:`quick` (5 项关键风险) / `full` (完整 25 项)

## 评审清单(权重见百分比)

### 1. 信息层(20%)
- [ ] 数据是否覆盖决策者关心的核心 KPI?
- [ ] 有"决策者关心却被砍了"的数据吗?
- [ ] 有"决策者根本不关心却占 C 位"的数据吗?
- [ ] 关键数字有没有用大字号/品牌色突出?

### 2. 布局层(25%)
- [ ] P0 数据在视觉中心吗?
- [ ] 信息层次清晰吗(主标 > 副数据 > 装饰)?
- [ ] 预留了适配三比例的栅格结构吗?
- [ ] 两侧是否是可砍的次要数据?
- [ ] 是否固定了"次要侧"?

### 3. 适配层(20%)
- [ ] 提供了几种比例方案?(理想:19:6 + 4:3 + 21:9)
- [ ] 在最窄比例下,P0 数据还在吗?
- [ ] 拉伸/挤压时关键元素会不会变形?

### 4. 视觉层(25%)
- [ ] 主配色撞客户行业高危标志色了吗?(对照禁忌表)
- [ ] 视觉风格(质感/光效/字体)匹配客户的"高级感锚"吗?
- [ ] 字号够大吗?(最远观看距离测试)
- [ ] 关键数据一眼能读到吗?

### 5. 受众层(10%)
- [ ] 第一受众是谁?和呈现内容匹配吗?
- [ ] 决策者本位 vs 执行层本位,有没有混淆?

## 评审报告模板

```markdown
# 大屏设计评审:<项目名>

## 总评:X / 100
- 信息层:X / 20
- 布局层:X / 25
- 适配层:X / 20
- 视觉层:X / 25
- 受众层:X / 10

## 🔴 高风险(必改 — 不改可能导致客户当场吐槽)
1. [问题] → [建议改法] → [所属步骤/原则]

## 🟡 中风险(建议改)
1. ...

## 🟢 加分建议(可选)
1. ...
```

## 守护栏(skill 自我约束)

1. **不跳步**:design 模式必须按 1→2→3→4→5→6 顺序,跳步直接做视觉是大屏翻车第一原因。
2. **禁忌色表是经验值,不是真理**:必须用 Step 3 的客户实际观察校准。如果观察结果和速查表冲突,以观察为准。
3. **19:6 是默认基准,不是硬规定**:如果客户硬件已知,以客户硬件为基准比例。
4. **决策者本位 ≠ 唯一答案**:7×24 小时指挥中心场景,要切换成执行层本位 — 此时本 skill 部分原则不适用,要在产出文档里明确标注。
5. **不要用 C 端的"用户访谈+问卷"硬套 B 端**:接触不到客户时用观察法,不要说"建议做用户访谈"。
6. **行业报告 ≠ 真理**:报告口径会变,要交叉验证 5-10 年是否一直在提。
