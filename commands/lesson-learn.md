从当前对话中提取「经验教训」，保存为独立案例文档到 `~/Documents/cc-lesson-learn/`，供日后快速检索复用。

## 与其他命令的关系

```
/save-discussion  → 保存完整讨论内容（忠实记录）
/absorb          → 提取知识单元路由到规则文件
/lesson-learn    → 专注「踩坑→解决→下次怎么做」的案例沉淀（本命令）
```

## 输入参数

用户提供的话题关键词：`$ARGUMENTS`

如果未提供，从对话中自动提取（英文小写中划线，≤5词，如 `feishu-doc-sync`）。

---

## Phase 1：扫描踩坑点

回顾当前对话完整历史，提取所有**有复用价值**的经验，重点识别：

| 类型 | 识别方式 | 示例 |
|------|---------|------|
| **操作失误** | 执行了错误命令/步骤，导致问题 | 未经确认 rm -rf 删了数据文件 |
| **工具陷阱** | API/CLI/工具的非显然行为 | lark-cli inline 公式需用 `<equation>` 而非 `$` |
| **环境差异** | 本地 vs 服务器 / bot vs user 身份差异 | bot 身份看不到用户云空间资源 |
| **流程缺陷** | 缺少确认步骤/验证步骤导致返工 | 创建文档后没验证内容是否正确渲染 |
| **认知偏差** | 错误假设导致绕弯 | 以为 wiki URL 的 token 可以直接用 |

**只提取对话中实际发生的，不编造。**

---

## Phase 2：组织内容

对每个踩坑点，提炼以下四要素：

1. **问题**（What happened）：一句话描述发生了什么
2. **原因**（Why it happened）：根本原因，而非表象
3. **解法**（How to fix）：具体操作步骤或命令
4. **行动指南**（Next time）：下次遇到同类情况，直接的行动指令（可直接照做，无需回忆上下文）

---

## Phase 3：写入文件

**文件名**：`YYYY-MM-DD-<话题关键词>.md`，日期取当天。

**保存路径**：`~/Documents/cc-lesson-learn/`（不存在则用 Bash 工具创建）

**文件模板**：

```markdown
---
date: YYYY-MM-DD
tags: [工具名, 场景类型, ...]
topic: 一句话主题（中文）
---

# 标题（体现核心教训，如：飞书文档行内公式不能直接用 $ 符号）

> 涉及工具/场景：xxx | 对话日期：YYYY-MM-DD

## TL;DR（30秒速查）

- ✅ 下次遇到 X，直接 Y
- ❌ 不要 Z（原因一句话）

---

## 踩坑经过

（简述问题背景和发生过程，3~5句话）

## 根本原因

（解释为什么会出现这个问题，技术层面的解释）

## 解决方案

（具体步骤，包含可直接复制的命令/代码/配置）

## 行动指南（完整版）

针对此类问题的 checklist 或决策树，写给"三个月后完全忘记上下文的自己"：

- [ ] 步骤一
- [ ] 步骤二
- [ ] ...

## 相关资源

（文档链接、文件路径、命令参考等）
```

## 注意事项

- **行动指南要能直接照做**：读者是三个月后的自己，假设完全忘记上下文
- **命令要完整**：`lark-cli docs +create --title "xxx" --markdown "$(cat /tmp/xxx.md)"` 而不是"使用 lark-cli 创建"
- **一份文件一个话题**：如对话覆盖多个不相关踩坑，拆分为多个文件
- **不记流水账**：省略探索过程，只保留结论
