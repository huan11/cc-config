对指定仓库做静态结构分析，生成仓库地图，写入目标仓库的 `docs/repo-map-{项目名}-{YYYY-MM-DD}.md`。

目标仓库路径: $ARGUMENTS

如果未提供路径，使用当前工作目录。

## 命令族导航

本命令与 `make-*` 系列互补，专注于**文件级静态结构**：

- `/make-repo-card` — 项目是什么（身份卡片）
- **`/make-repo-map`** ← 当前：项目长什么样（文件地图 + 数据串联）
- `/make-repo-behaviors` — 项目做了什么（业务规则）
- `/make-exec-flow` — 怎么跑起来的（运行时执行流）

## 产出物

`docs/repo-map-{项目名}-{YYYY-MM-DD}.md` — 仓库地图（文件名包含项目名和扫描日期）

## 执行流程

### Phase 1: 目录全景扫描

1. 在目标仓库根目录执行 `find . -maxdepth 4 -not -path './.git/*' -not -path './node_modules/*' -not -path './__pycache__/*' -not -path './venv/*' -not -path './.venv/*' | head -120`
2. 识别目录设计意图：
   - 按层分类：入口层、业务逻辑层、数据层、配置层、工具层、测试层
   - 标注每个目录的职责（一句话）
3. 如果是 monorepo，询问用户：整体出图还是选子模块

### Phase 1.5: 代码统计

1. 执行 `cloc --by-file --not-match-d='.git|__pycache__|node_modules|venv|.venv' --not-match-f='副本|backup|old' .`
   - 如果 `cloc` 未安装，降级用 `wc -l` 逐文件统计
2. 记录：
   - **按语言汇总**：语言、文件数、空行、注释行、代码行
   - **按文件明细**（代码行降序）：文件路径、代码行、注释行、占比
3. 标注最大文件和代码集中度（前 3 大文件占总量百分比）

### Phase 2: 文件逐一标注

对每个代码文件（跳过备份文件、`__pycache__`、`.pyc`）：

1. **快速阅读**文件头部（前 30-50 行），提取：
   - 文件职责（一句话）
   - 主要类/函数名（不需要全部，只列关键的）
   - 该文件的 import 列表（项目内 import，忽略标准库和第三方包）
2. **判断文件重要性**：
   - **入口文件** (Entry): 程序执行的起点（含 `__main__`、被 .bat/.sh 调用、被调度系统触发）
   - **核心文件** (Core): 实现主要业务逻辑
   - **辅助文件** (Support): 配置管理、工具函数、数据准备
   - **配置文件** (Config): YAML/JSON/INI 等静态配置
   - **脚本文件** (Script): .bat/.sh 等触发脚本
   - **测试文件** (Test): 测试代码
   - **废弃/备份** (Deprecated): 备份文件、副本文件

### Phase 3: 文件关系图谱

1. **调用关系**：从每个文件的 import 语句，画出「谁导入了谁」的有向图
2. **层级关系**：入口文件 → 核心文件 → 辅助文件 → 配置文件
3. 用 ASCII 图表示文件调用关系（不需要画出所有文件，只画核心链路）

### Phase 4: 数据串联分析（本命令的核心差异点）

这是本命令最重要的部分。目标是回答：**一条数据从进入系统到最终落地，经过了哪些文件？**

1. **识别数据对象**：找出系统中流转的核心数据对象（DataFrame、dict、list 等），给每类数据一个业务名称
2. **追踪数据流转路径**：对每个核心数据对象，记录：
   - 数据从哪个文件的哪个函数**产生**（读取/创建）
   - 经过哪些文件的哪些函数**加工**（计算/转换/合并）
   - 最终在哪个文件的哪个函数**落地**（写入数据库/文件/外发）
3. **画数据流转图**：用 ASCII 图表示核心数据的流转路径，标注每一跳经过的文件和函数

### Phase 6: 展示确认

展示以下摘要（不贴全文）：

- **代码规模**: 总文件数、总代码行数、最大文件及占比
- **目录结构**: X 个目录，按 N 层组织
- **文件分布**: 入口 X 个、核心 X 个、辅助 X 个、配置 X 个
- **核心数据流**: 列出识别到的核心数据对象及其流转概要
- **关键发现**: 有无孤立文件、循环依赖、废弃代码等

## 守护栏

- **只抓结构，不读业务细节** — 每个文件只读头部和 import，不逐行分析业务逻辑（那是 `/make-repo-behaviors` 的工作）
- **数据流追踪到文件粒度** — 追踪数据在文件间的流转，不深入函数内部的每一行（那是 `/make-algo-flow` 的工作）
- **信息来自代码事实** — import 语句、函数签名、变量传递都必须来自代码，不确定的标"待确认"
- **目标仓库只读** — 只写 `docs/repo-map.md`，不修改任何已有文件
- **废弃文件要标出但不深入分析** — 带"副本"、"backup"、"old"后缀的文件标为废弃，不浪费精力分析
- **产出后等确认** — 展示摘要，等用户确认再结束
