对技术文章进行 7 个维度的深度拆解分析，萃取核心知识并生成结构化学习笔记。

> 综合了 Quiet Star + Tree of Thoughts + LangGPT 结构化 + Chain-of-Thought + 费曼学习法

## 参数

- **source**：文章 URL 或本地文件路径（缺少时询问）

## 第一步：获取文章内容

根据 source 类型：

| 类型 | 获取方式 |
|------|---------|
| URL | WebFetch 抓取完整内容，要求不要摘要，保留所有段落/代码/标题 |
| 本地文件 | Read 工具读取 |
| 用户粘贴 | 直接使用 |

如果 WebFetch 内容不完整（明显被截断），尝试第二次抓取补充。

## 第二步：7 维度深度分析

基于获取到的完整文章内容，逐维度分析：

### 维度 1: 元信息提取 (Meta)
- 文章标题、作者、发布平台、目标受众
- 文章类型判定：教程 / 科普 / 评测 / 观点文 / 技术方案
- 一句话概括：这篇文章在回答什么问题？

### 维度 2: 知识结构拆解 (Structure)
- 用 ASCII 树状图展示文章的知识层次结构
- 标注每个章节的功能角色：引入 / 定义 / 论证 / 举例 / 对比 / 总结
- 识别文章的核心论点（Thesis）和支撑论点（Sub-thesis）

### 维度 3: 核心概念萃取 (Concepts)
- 列出所有关键术语和概念，用一句话解释每个
- 标注概念之间的关系：包含 / 对比 / 依赖 / 演进
- 用表格呈现：概念 | 定义 | 与其他概念的关系 | 重要程度(★1-5)

### 维度 4: 论证逻辑分析 (Logic)
- 作者的核心主张是什么？
- 用了哪些论证手法？（数据 / 类比 / 权威引用 / 反证 / 案例）
- 论证链条是否完整？是否存在逻辑跳跃？
- 有哪些隐含的前提假设？

### 维度 5: 批判性审视 (Critical)
- 文章的潜在偏见（作者立场、商业利益、技术栈偏好）
- 被刻意忽略或轻描淡写的反面观点
- 哪些结论有充分证据支撑？哪些是作者的主观判断？
- 与业界其他观点的冲突或互补

### 维度 6: 可执行知识提取 (Actionable)
- 读完这篇文章，我可以立刻做的 3 件事
- 关键代码片段 / 命令 / 配置（如有）
- 需要进一步学习的前置知识
- 推荐的后续阅读路径

### 维度 7: 记忆锚点 (Memory Anchors)
- 用 3 个类比/比喻帮助记忆核心概念
- 设计 3 个自测问题（附答案），用于检验是否真正理解
- 一段 50 字以内的"电梯演讲"：如何向别人解释这篇文章

## 第三步：保存分析文件

保存到当前项目的 `docs/article-analysis/` 目录（不存在则创建）。

文件命名：`analysis-<slug>.md`，slug 从文章标题生成。

文件头部格式：

```markdown
# 深度拆解：<文章标题>

> 原文: <URL 或文件路径>
> 分析日期: YYYY-MM-DD
> 分析框架: 7 维度深度拆解 v1.0

---
```

## 写作原则

- 使用中文，保留英文技术术语
- 保持客观立场，不盲目赞同也不刻意否定
- 区分「文章说了什么」和「事实是什么」
- 信息不足以做判断时，明确标注「信息不足」
- 关键概念使用**粗体**，批判性观点使用 `>` 引用块
- 代码使用代码块，关系使用表格

## 守护栏

- 不编造文章中没有的内容
- 不跳过任何维度，每个维度都必须有实质内容
- 批判性审视必须同时指出优点和缺点
- 记忆锚点的类比必须对非专业人士也能理解
- 自测问题必须附带参考答案
