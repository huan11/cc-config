项目环境检查与启动执行器。先检查环境，再决定是否执行启动操作。

## 第 1 步：环境检查（只读）

扫描项目根目录，识别语言、包管理器、框架、依赖服务。读取 CLAUDE.md / README.md 了解项目约定。

### 检查项

**数据和文件：**
- 有 `*.example` / `*.sample` 但缺少对应实际文件的配置
- 配置中引用的目录和文件是否存在
- 被 .gitignore 排除但运行必需的文件

**软件环境：**
- 语言运行时版本是否满足要求
- 依赖包是否已安装
- Docker 服务是否在运行
- 数据库/缓存等服务是否可连接（禁止输出密码）
- 必需的数据库表/集合是否存在
- 环境变量是否已设置

**配置合理性：**
- 占位符是否已替换（`your_*`、`TODO`、`CHANGE_ME`）
- 路径是否指向真实存在的位置
- 端口等关键值是否与 docker-compose / CLAUDE.md 一致

### 检查结果输出

输出一张状态总表：

| # | 检查项 | 状态 | 备注 |
|---|--------|------|------|
| 1 | Python 版本 | ✅ | 3.12 |
| 2 | .env 文件 | ❌ | 缺少，需从 .env.example 复制 |

全部通过 → 输出"环境检查通过，项目可以启动"。

有问题 → 按 P0/P1/P2 优先级排序输出修复清单，询问用户：

**环境检查完成。选择下一步：（0=仅查看不修复 / 1=自动执行修复和启动）**

用户选 0 → 结束。
用户选 1 → 进入第 2 步。

## 第 2 步：规划启动任务

根据检查结果，用 TaskCreate 创建完整任务列表，覆盖以下适用项（按顺序）：

**环境准备：**
- 检查语言运行时版本
- 创建虚拟环境（Python: `uv venv`）
- 安装依赖包（Python: `uv pip install`）
- 验证依赖安装结果

**配置准备：**
- 从 `.example` 复制生成实际配置文件
- 检查占位符，列出需要用户手动填写的项
- 创建缺失的目录

**服务连通性：**
- 检查数据库连通性（禁止输出密码）
- 检查 Docker 服务
- 检查缓存/消息队列等

**验证：**
- 运行入口脚本的最小化验证
- 运行测试（如有）

任务列表展示给用户确认后开始执行。

## 第 3 步：逐项执行

- 每个任务执行前 TaskUpdate 为 `in_progress`
- 成功 → `completed`
- 失败 → 保持 `in_progress`，记录错误，尝试继续下一个不依赖它的任务
- 需要用户输入的步骤 → 暂停提示
- Python 项目必须使用 uv

## 第 4 步：错误记录

在项目根目录创建 `SETUP_ERRORS.md`：

```markdown
# Setup Errors — {日期}

| # | 任务 | 错误类型 | 状态 |
|---|------|---------|------|
| 1 | 安装依赖 | 版本冲突 | 已修复 ✅ / 未解决 ❌ |
```

每次命令执行失败都必须记录，包括后来修复的。

## 第 5 步：输出最终报告

| # | 任务 | 状态 | 备注 |
|---|------|------|------|
| 1 | 创建虚拟环境 | ✅ | .venv 已创建 |
| 2 | 数据库连通性 | ❌ | 本地 MySQL 不可达 |

全部 ✅ → **"项目启动完成"**
有 ❌ → 输出未解决项，将遗留问题追加到 TODO.md

## 守护栏

- 不猜测密码和 API Key，需要用户输入的必须暂停询问
- 不执行破坏性操作（`rm -rf`、`git reset --hard`）
- 不修改已有的业务代码文件
- 每步执行前确认命令合理性，不盲目重试超过 2 次
- 所有错误必须记录，不得静默吞掉
