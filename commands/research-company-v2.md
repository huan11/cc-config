对目标公司进行合作评估导向的深度调研。目标不是堆信息，而是回答三个问题：

1. 这家公司值不值得接触或推进？
2. 如果值得，最合适的合作方式是什么？
3. 当前最大的风险、信息缺口和下一步动作是什么？

## 参数

- **$ARGUMENTS**：要调研的公司名称（缺少时询问）

## 默认策略

优先保证决策价值，而不是报告长度。

- 用户没有补充背景时，默认按“**标准评估** + **先全面了解**”执行
- 用户说“直接开始”时，不再连续追问，只补一个最关键问题；若用户仍不补充，则带着明确假设继续
- 信息不足时，允许输出“当前公开信息下的初步判断”，不要为了凑完整而机械扩写

## 第一步：快速定标

最多先问 **2 个问题**，避免启动成本过高：

1. **这次评估的合作方向是什么？**
   技术合作 / 渠道合作 / 投资并购 / 供应商评估 / 战略合作 / 先全面了解
2. **我方画像是什么？**
   我们卖什么、想从这家公司获得什么、当前最关心什么

如果用户没有提供我方画像，则在报告开头显式写出：

> 以下互补性与合作建议，基于“我方希望寻找具备业务协同或资源协同潜力的合作对象”这一通用假设。

## 第二步：选择调研深度

根据用户意图自动选择模式：

| 模式 | 适用场景 | 目标 | 参考来源量 |
|------|----------|------|-----------|
| 快速筛选 | 先判断值不值得继续聊 | 15 分钟内形成 go / no-go 初判 | 5-8 |
| 标准评估 | 默认模式 | 形成可用于内部讨论的合作建议 | 8-12 |
| 深度尽调 | 投资并购、重大合作、签约前评估 | 尽可能补齐治理、财务、合规与关键风险 | 12-20 |

用户未指定时，默认使用 **标准评估**。

## 第三步：多源取证

先确认是不是同名公司、子公司、品牌名或海外主体，必要时注明本次调研对象的完整名称。

按以下优先级取证，质量优先，找不到就标注，不凑数：

| 优先级 | 来源 | 重点看什么 |
|--------|------|-----------|
| P0 | 官网、企业公告、年报/招股书、投资者关系页面、监管披露 | 官方定位、产品、客户、财务、管理层、重大事项 |
| P1 | 国家企业信用信息公示、企查查/天眼查、法院/知识产权公开信息 | 主体信息、股权、诉讼、行政处罚、知识产权 |
| P2 | 权威媒体、行业媒体、创始人/高管访谈、公开演讲 | 战略方向、融资、市场动作、管理风格 |
| P3 | 产品文档、开发者文档、招聘页、客户案例、生态合作页 | 技术能力、开放能力、招聘方向、合作模式 |
| P4 | 券商/咨询摘要、行业报告摘要 | 行业格局、市场规模、可比公司 |
| P5 | 社区讨论、员工评价 | 作为弱信号补充，不单独作为关键结论依据 |

执行要求：

- 对最有价值的页面做深入读取，不追求来源数量，追求“关键判断有证据”
- 上市公司优先看最近一个完整财年和最近一次正式披露
- 非上市公司财务稀缺时，用融资历史、客户质量、招聘节奏、产品成熟度、管理层稳定性做替代判断，但必须标注为间接信号
- 多个来源矛盾时，列出不同说法、日期和来源，不替用户强行拍板
- 财务、诉讼、处罚、股权等高风险信息必须给出来源

## 第四步：按合作方向调整关注重点

不同合作方向，评分维度和取证重点不同：

### 技术合作

重点看：
- 技术栈兼容性
- API / SDK / 开放平台成熟度
- 数据安全、权限边界、集成复杂度
- 技术团队实力与响应能力

### 渠道合作

重点看：
- 产品是否易卖
- 定价与毛利空间
- 是否已有渠道体系与渠道冲突
- 标杆客户、销售周期、交付复杂度

### 投资并购

重点看：
- 主体与股权结构
- 财务健康度与融资历史
- 实控人稳定性
- 合规、诉讼、历史争议、组织依赖性

### 供应商评估

重点看：
- 交付能力与 SLA
- 客户集中度
- 财务稳定性
- 合规资质、服务风险、替代成本

### 先全面了解 / 战略合作

重点看：
- 业务方向
- 行业位置
- 合作可能性
- 风险边界

## 第五步：形成证据矩阵

至少覆盖以下判断项；没有公开信息时如实标注：

| 判断项 | 需要回答的问题 |
|--------|---------------|
| 公司是谁 | 主体、阶段、定位、核心业务是什么 |
| 靠什么活着 | 商业模式、客户、收入来源是什么 |
| 发展得怎么样 | 增长、融资、市场动作、组织扩张是否健康 |
| 和谁竞争 | 行业位置、核心竞品、优势短板是什么 |
| 有没有合作基础 | 现有生态、开放程度、合作历史如何 |
| 风险大不大 | 财务、合规、诉讼、数据、团队、战略波动风险 |
| 值不值得推进 | 与我方的互补性、进入难度、潜在回报如何 |

## 第六步：输出报告

保存到 `docs/company-research/<company-slug>.md`（目录不存在则创建）。

先给结论，再给论据。报告以“能否推进合作决策”为中心，而不是百科式罗列。

### 写作原则

- **结论先行**：每章开头先给核心判断
- **事实与判断分离**：事实给来源；判断标注“基于公开信息判断”
- **只写有决策价值的信息**：与合作无关的材料少写或不写
- **允许信息缺口**：缺就写缺口，不拿猜测填空
- **用自己的话组织**：禁止大段搬运原文
- **先摘要，后展开**：让读者先看到 go / no-go 与风险

## 七、产品、技术与交付能力

## 输出裁剪规则

- **快速筛选**：重点保留第 1、3、4、5、9、10、11、12 章
- **标准评估**：使用完整模板，但允许第 6、7、8 章按资料情况压缩
- **深度尽调**：完整展开第 6、7、9、10、12 章

不要机械要求每一章都写很长。重点在于“关键判断是否成立”。

## 守护栏

- 禁止编造 URL、客户、财务数字、股权数据、诉讼信息
- 财务数字、处罚、诉讼、股权、融资等高风险信息必须给来源
- 区分“事实”“公开信号”“基于公开信息判断”
- 多个来源冲突时，写清楚日期、来源和差异，不强行统一
- 如果无法确认主体身份，先说明歧义，再继续
- 如果不了解我方业务，不得假装精准做互补性分析，必须写明假设
- 不要为了“完整”而硬凑十四章；没有证据的部分写“未找到公开信息”或“不适用”
- 最终建议必须可执行，不能只写空泛结论
