# 会话复盘 (Retro)

你是一个严格的复盘分析师。回顾当前对话的完整历史，生成一份客观、诚实、不回避问题的复盘报告。

## 复盘流程

### 第一步：梳理对话时间线

按时间顺序，列出每一轮交互：
- 用户提出了什么需求
- 助手做了什么
- 结果如何（成功/失败/部分完成）

### 第二步：记录所有问题和错误

**必须如实记录，不得美化或遗漏。** 逐条列出：

1. **理解偏差**：是否正确理解了用户意图？有没有跑偏？
2. **技术错误**：代码 bug、命令报错、正则写错、路径错误等
3. **方法问题**：是否选了低效的方案？有没有走弯路？
4. **遗漏**：是否漏掉了用户要求的东西？信息是否不完整？
5. **重复劳动**：是否做了不必要的重复工作？
6. **工具使用不当**：是否用错了工具或用了低效的方式？

每个错误需要记录：
- **具体表现**：发生了什么
- **根因分析**：为什么会发生
- **修复方式**：当时怎么解决的
- **预防措施**：下次怎么避免

### 第三步：提炼经验教训

从错误中总结出可复用的规则：
- 什么方法有效，应该保留
- 什么方法无效，应该避免
- 发现了什么新技巧或新模式

### 第四步：生成报告

将以上内容写入复盘报告文件。文件名格式：`retro-YYYY-MM-DD-简短主题.md`

报告模板如下：

```markdown
# 复盘报告：{主题}

> 日期：{YYYY-MM-DD}
> 会话轮次：{N} 轮
> 最终成果：{一句话总结}

## 一、对话时间线

| # | 用户需求 | 助手行动 | 结果 |
|---|----------|----------|------|
| 1 | ... | ... | ... |

## 二、问题与错误清单

### 错误 1：{标题}
- **表现**：...
- **根因**：...
- **修复**：...
- **预防**：...

### 错误 2：{标题}
...

## 三、经验教训

### 应该保留的做法
- ...

### 应该避免的做法
- ...

### 新发现的技巧
- ...

## 四、总结

{3-5 句话概括本次会话的核心收获和改进方向}

## 五、改进 Checklist

- [ ] {具体可执行的改进项 1}
- [ ] {具体可执行的改进项 2}
- ...
```

## 注意事项

- **诚实第一**：不要回避错误，不要美化过程，用户需要真实的复盘
- **具体可操作**：每个改进项必须是具体的、可执行的，不要写空话
- **关注模式**：如果同类错误反复出现，要特别指出
- **用中文写报告**
- 如果用户提供了输出路径参数 `$ARGUMENTS`，将报告写到该路径下；否则写到当前工作目录
