对指定仓库做轻量级取证，生成仓库身份卡片，写入目标仓库的 `docs/repo-card.md`。

目标仓库路径: $ARGUMENTS

如果未提供路径，立即询问用户，不要猜测。

## 命令族导航

本命令是 `make-*` 系列的第一步，建议按顺序使用：

1. **`/make-repo-card`** ← 当前：这是什么
2. `/make-repo-behaviors` — 做了什么、遵循什么规则
3. `/make-exec-flow` — 怎么跑起来的（宏观执行流）
4. `/make-algo-flow` — 具体怎么算的（微观算法流程）

## 产出物

`docs/repo-card.md` — 仓库身份卡片

## 执行流程

### Phase 1: 信息采集（目标仓库只读）

1. 先看全貌 — 在目标仓库根目录执行 `find . -maxdepth 3 -not -path './.git/*' | head -80`，建立目录心智模型
2. 判断仓库类型：
   - 如果识别到 monorepo（多个 `pyproject.toml`/`package.json`/`pom.xml`，或 `services/`、`packages/` 目录），询问用户：对整体出一张概览卡，还是选某个子模块单独出卡
   - 单仓库直接继续
3. 读取 `CLAUDE.md`、`README.md`、`TODO.md`、`CHANGELOG.md`（如有）
4. 识别项目语言/框架，读取依赖声明文件：
   - Python: `pyproject.toml` / `requirements.txt`
   - Java: `pom.xml` / `build.gradle`
   - Node: `package.json`
   - 其他: 按实际情况识别
5. 读取 SQL 目录（`sql/`、`*.sql`），提取数据库依赖（库名、表名、读/写）
6. 读取主入口文件，理解运行模式
7. 快速浏览核心代码文件（不逐行，只追踪主流程链路）
8. 读取配置文件（`config/`、`*.yaml`、`*.json`、`*.ini`、`.env.example`），识别外部系统依赖

### Phase 2: 生成 repo-card.md

按以下模板填写，写入目标仓库的 `docs/repo-card.md`。

模板中所有节都是可选的 — **无内容的节直接删除，不留空表格。** 一个简单脚本可能只有项目定位、技术栈、主入口三节，这完全正常。

```markdown

> 取证日期: YYYY-MM-DD
> 仓库路径: [path]

## 项目定位
<!-- 一句话说清楚这个项目做什么 -->

## 技术栈
| 维度 | 选型 |
|------|------|
| 语言 | |
| 框架 | |
| 包管理 | |
| 运行时版本 | |

## 主入口
| 入口文件 | 触发方式 | 说明 |
|---------|---------|------|

<!-- 支持多种模式（daily/history/manual/server 等）时才保留本节 -->

| 文件 | 格式 | 用途 |
```

### Phase 3: 展示确认

产出完成后，向用户展示以下摘要（不贴全文）：

- **项目定位**: 一句话
- **技术栈**: 语言 + 框架
- **主入口**: 几个入口、怎么触发
- **外部系统依赖**: 依赖了哪些外部系统

然后告知用户完整卡片已写入 `docs/repo-card.md`，等待确认或修改意见。

## 守护栏

- **只抓关键信息** — 这是快速摸底，不是穷举审计。遗漏边角信息比花两小时读完每一行代码要好得多。
- **信息来自代码事实** — 不确定的标"待确认"。编造一条看起来合理的信息比留白危害更大，因为后续命令会基于这张卡片工作。
- **目标仓库只读** — 只写 `docs/repo-card.md`，不修改任何已有文件。
- **产出后等确认** — 展示摘要，等用户确认再结束。
