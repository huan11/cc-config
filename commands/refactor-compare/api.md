按功能点（用户故事）逐一检查重构前后基金页面的 API 调用是否一致。

## 项目路径

- **旧项目 (Old)**: `ratel-mind-web/` — React + Vite
- **新项目 (New)**: `website-next/` — Next.js 14 (App Router)
- **验收基准**: `ratel-mind-web-fund-acceptance-v2.md`

## 核心思路

**以功能点为驱动，而非以 API 列表为驱动。**

对验收文档中的每个用户故事（US-01 ~ US-16），执行以下流程：
1. 明确该功能点涉及哪些用户交互（如"点击基金卡片"、"切换基准"）
2. 追踪旧项目中该交互触发了哪些 API 调用（从页面组件 → service 函数 → HTTP 请求）
3. 追踪新项目中相同交互触发了哪些 API 调用
4. 对比两端的 API 调用链是否一致

## 执行流程

### 1. 读取验收文档

读取 `ratel-mind-web-fund-acceptance-v2.md`，理解每个用户故事的 AC 和对应的 API 调用清单。

### 2. 逐功能点检查

对每个功能点（US-01 ~ US-16）：

**Step A: 追踪旧项目的调用链**
- 找到旧项目中实现该功能的页面组件代码
- 追踪：用户交互 → 事件处理函数 → service 调用 → HTTP 请求（方法 + 路径 + 参数）
- 记录完整调用链

**Step B: 追踪新项目的调用链**
- 找到新项目中实现相同功能的组件/hook 代码
- 追踪相同的调用链
- 记录完整调用链

**Step C: 对比**
- API 路径是否相同？
- HTTP 方法是否相同？
- 请求参数是否相同？（缺少参数 / 多出参数 / 参数名变化）
- 调用时机是否相同？（同一个交互是否触发同样的 API）
- 是否有旧项目调了但新项目没调的 API？
- 是否有新项目额外调了旧项目没有的 API？
