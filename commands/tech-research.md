---
description: 六维技术深度调研（灵感来自左耳朵耗子的技术学习方法论）
argument-hint: <技术名称>
---

对用户指定的技术进行六维深度调研，输出结构化分析报告。

## 参数

- **$ARGUMENTS**：要调研的技术名称（缺少时询问）

## 执行流程

### 第一步：确认调研范围

先问用户：

1. 你对这个技术目前了解多少？（零基础 / 听说过 / 用过一点 / 有一定经验）
2. 调研目的是什么？（技术选型 / 深入学习 / 面试准备 / 纯好奇）
3. 有没有特别想搞清楚的问题？

用户说"直接开始"则按零基础+深入学习处理。

### 第二步：多源搜索

按优先级搜索，质量优先，找不到就跳过，不凑数：

| 优先级 | 来源 | 获取方式 |
|--------|------|---------|
| P0 | 官方文档、设计文档、论文 | WebSearch -> WebFetch |
| P1 | GitHub 仓库（star、issue、release） | WebSearch / `gh` 命令 |
| P2 | 作者/核心团队的博客、演讲、RFC | WebSearch -> WebFetch |
| P3 | 权威横向对比、基准测试 | WebSearch |

- WebFetch 只对最有价值的 3-5 个页面使用
- 6 个维度都有可靠来源后停止
- 搜不到的维度标注"未找到可靠来源"

### 第三步：输出报告

保存到 `docs/tech-research/<topic-slug>.md`（目录不存在则创建）。

**写作原则：**

- **第一性原理**：区分"基本约束"（任何方案都绕不开的）和"设计选择"（可以不同的）
- **费曼标准**：用自己的话解释，禁止搬运原文。标准：不懂这技术的工程师能看懂
- 讲不清楚的诚实标注"此处需进一步理解"
- 每个维度给出核心结论，再展开论述

**报告模板：**

```markdown
# <技术名称> 技术调研

> 调研时间: YYYY-MM-DD

## 一句话定位

用一句话说清楚这个技术是什么、做什么的。

---

## 1. 背景与动机（技术的灵魂）

- 这个技术出现之前，同样的问题是怎么解决的？痛点在哪？
- 创造者的初衷和设计目标是什么？
- 这个领域的**基本约束**是什么？（任何方案都绕不开的物理限制、理论限制）

> 不搞清楚"为什么出现"，就看不懂后面的设计决策。

## 2. 优势、劣势与 Trade-off

**优势：** 解决了什么问题，比之前的方案好在哪

**劣势：** 引入了什么新问题、新复杂度

**核心 Trade-off：**
- 面对基本约束，选择了什么、放弃了什么？
- 这些取舍是被约束逼的，还是设计者的主观偏好？
- 有哪些隐含的假设？

> 任何技术都有好坏，关键是看清它选择了什么、放弃了什么。

## 3. 适用场景

**业务场景：** 什么业务用它最合适

**技术场景：** 什么技术条件下它能发挥优势

**反模式：** 什么情况下不该用它（以及为什么有人误用）

> 离开场景谈技术没有意义。没有银弹。

## 4. 核心组成与关键点

- 核心概念/抽象是什么？
- 核心组件及其职责
- 组件之间的关系（如有必要画 ASCII 架构图）
- 最小可理解模型：抓住这几个点，其余按需学

> 用最少的信息让读者抓住骨架。

## 5. 底层原理与关键实现

- 依赖哪些底层基础技术？
- 关键算法/协议/数据结构是什么？
- 这些基础技术是否也被其他技术复用？（学会它们能加速学习其他技术）
- 从输入到输出，数据/请求的完整流转路径是什么？

> 底层基础技术是可复用的学习资产。

## 6. 横向对比

| 维度 | <本技术> | <竞品A> | <竞品B> |
|------|----------|---------|---------|
| 定位 | | | |
| 核心 Trade-off | | | |
| 适用场景 | | | |
| 社区生态 | | | |
| 学习曲线 | | | |

- 面对同样的基本约束，各方案为什么做了不同的选择？
- 设计哲学上的根本分歧是什么？

---

## 费曼检验

用大白话把这个技术从头到尾串一遍。
不用术语（用了必须当场解释）。
标准：完全不了解这技术的工程师读完能建立基本认知。
写不出大白话的部分标注为开放问题。

## 开放问题

没搞清楚、讲不明白、或来源矛盾的问题，指明下一步学习方向。

## 学习路径

1. **入门**（1-2 个资源）：快速建立认知
2. **上手**（1-2 个资源）：跑通 Hello World
3. **深入**（1-2 个资源）：理解原理
4. **实战**（1-2 个资源）：生产级经验

## 参考资料

（附带 URL，标注来源类型：官方文档/论文/博客/视频）
```

## 守护栏

- 禁止编造 URL，搜不到标注"未找到"
- GitHub 数据用 `gh` 命令或 WebSearch 实时获取，禁止凭记忆编数字
- 事实给来源，观点标注"社区主流观点"或"个人判断"
- 每个维度下的引用语（>）输出时保留，它们是给读者的学习提示
- 六个维度缺一不可，搜不到的标注原因，不能静默跳过
