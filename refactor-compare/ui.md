以旧项目为基准，通过浏览器自动化操作 + 截图，逐功能点对比新项目的 UI 表现，找出视觉和交互问题。

## 前置条件

- 旧项目 (ratel-mind-web) 运行在 `http://localhost:5173/ratel/fund`
- 新项目 (website-next) 运行在 `http://localhost:3000/funds`
- 两个系统使用同一后端，确保数据一致
- 如果某个系统未启动，提示用户先启动，不要跳过

## 核心思路

**不是静态截图对比，而是"操作 + 截图"对比。**

每个测试场景 = 一组浏览器操作 + 一个截图检查点。先在旧网站执行获取基准截图，再在新网站执行相同操作获取对比截图，最后 AI 逐像素级对比两张截图找差异。

## 执行流程

### 1. 检查服务可用性

用 agent-browser 分别访问旧项目和新项目 URL，确认两个服务都在运行。

### 2. 以旧项目为基准执行测试

按「测试场景清单」的顺序，在**旧项目**上逐个执行：
1. 执行浏览器操作（点击、输入、滚动、等待）
2. 在检查点截图，保存到 `test-screenshots/baseline/` 目录
3. 文件名格式：`{场景编号}-{场景名}.png`（如 `1.2-自选分组标签.png`）

### 3. 在新项目上执行相同操作

在**新项目**上重复完全相同的操作序列：
1. 确保选择同一只基金（通过名称匹配）
2. 确保基准和时间范围与旧项目一致
3. 在相同检查点截图，保存到 `test-screenshots/current/` 目录

### 4. 逐场景对比

对每个场景，读取 baseline 和 current 两张截图，检查：

| 检查维度 | 具体内容 |
|---------|---------|
| 元素存在性 | 旧项目有的元素，新项目是否都有？（如分组名称、按钮、标签） |
| 文字内容 | 标题、标签、提示文字是否一致？ |
| 数据一致性 | 相同基金、相同基准、相同时间范围下，数值是否一致？ |
| 布局 | 元素排列、间距是否合理？（不要求像素级一致，但结构应相同） |
| 颜色 | 红涨绿跌、图表曲线颜色是否正确？ |
| 交互反馈 | 操作后的响应是否正确？（如切换标签后列表是否更新） |

### 5. 输出报告
